# Разработка

## Окружение

Используйте Node.js 24, npm и PostgreSQL 17. Основной пакет находится в `mvp`; начните с его README. Для тестирования нужен отдельный presentation-стенд или временная тестовая БД. Не подставляйте основную БД в команды сброса стенда.

`npm run dev` запускает только интерфейс Vite. Для работающего входа, сохранения и общения нужен сервер API: используйте штатный Docker- или presentation-запуск.

## Изменения

- Сохраняйте незавершённые изменения перед обновлением Git; используйте обычное объединение, без принудительного сброса и переписывания общей истории.
- Клиентский код — в `mvp/src`, сервер — в `mvp/server`, миграции — в `mvp/docker`, проверки — в `mvp/tests` и `mvp/scripts`.
- В репозитории поддерживается одна версия продукта; macOS-комплект собирается из тех же исходников.
- Отмечайте границы реальных интеграций и демонстраций. Не заменяйте серверное поведение успешным ответом заглушки.
- Не меняйте валидированные тексты опросников, исходные медицинские документы и лицензии без проверки источника.

## Проверки

Из `mvp`:

```sh
npm ci
npm run build
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
npm run test:integration
```

Интеграционная проверка требует PostgreSQL и локальные служебные настройки; она создаёт собственную временную БД. После изменений пользовательских путей выполните также `npm run test:browser` в исправном браузерном окружении. Сценарии и параметры перечислены в `mvp/README.md`.

GitHub Actions повторяет сборку и серверные проверки. `npm run check:release -- --build` проверяет состав поставки, ссылки в документации и отсутствие служебных артефактов.

## Перед отправкой

Проверьте состав `git diff` и `git status`. В коммит включаются исходники, lock-файлы, миграции, документация и публичные ресурсы. Секреты, реальные записи, пароли, дампы, node_modules, сборки и результаты QA остаются локальными. Справочные снимки распространяются отдельно с манифестом и проверкой целостности.
