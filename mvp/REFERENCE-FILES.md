# Хранение и чтение исходных документов

Основной режим — непрерывный текст с оглавлением и поиском по всему документу. Оригинальный PDF сохраняется побайтно. Таблицы, изображения и исходные страницы доступны для сверки; автоматического медицинского пересказа и OCR нет.

## Данные и файлы

Миграция `019-reference-files` оставляет метаданные, источник, версии, SHA-256, текст и разметку в `knowledge`. PDF и PNG находятся в `knowledge/archive/blobs/aa/bb/<sha256>` (настраивается `REFERENCE_FILES_DIR`). Одинаковые байты используют один объект. Архив не входит в Git; обязательно сохранять его вместе с БД.

Веб-процесс имеет SELECT в `knowledge` и доступ к архиву только для чтения. Путь строится исключительно из SHA-256; выход из каталога и симлинки внутри архива запрещены. Публичные справочные документы можно кешировать; личные записи, заметки, чат и приёмы сохраняют `no-store` и не входят в справочный снимок.

Офлайн-импортёр и `scripts/publish-reference-files.mjs` используют общий advisory lock. Для каждой записи файл пишется во временный объект, синхронизируется, публикуется атомарно без перезаписи и проверяется по SHA-256. Затем в транзакции обновляется ссылка и очищается bytea. До этого исходник остаётся в БД. Повторный запуск безопасен; прерванный запуск продолжается по записям. Невостребованные объекты автоматически не удаляются. Для полной сверки архива предусмотрен `--verify`.

Перенос освобождает логическое место в таблицах. Физические файлы PostgreSQL могут сохранить выделенное место; автоматического `VACUUM FULL` нет. Общий размер документов сам по себе не уменьшается от смены хранилища; уменьшается нагрузка на БД, повторная передача и дублирование одинаковых файлов.

## HTTP и читалка

- PDF и изображения: потоковая передача, GET/HEAD, одиночные byte ranges, 206/416, `Accept-Ranges`, `Content-Range`, SHA-256 ETag, `If-None-Match`, `If-Range`.
- Старые встроенные bytea читаются порциями по 256 КиБ до переноса. Целый PDF не загружается в память веб-процесса.
- URL с совпадающим `?v=<sha256>` имеет `public, max-age=31536000, immutable`. Без версии требуется перепроверка ETag. Несовпавшая версия возвращает 409; текстовый режим предлагает заново открыть актуальный индекс; новые байты не выдаются под старым ключом кеша.
- `/documents/:id/reader-index` отдаёт опубликованное оглавление, сведения о страницах, версии и хеши изображений. `/reader?from=N&limit=5&v=<revision>` загружает текст около видимой области. Все страницы сохраняют места и якоря в одном непрерывном документе.
- `/reader-search?q=...&v=...` ищет по заранее опубликованному нормализованному тексту всех страниц, включая ещё не загруженные. Подсветка использует те же блоки и смещения, что полный режим. Результаты поиска — `no-store`; поиск не является клинической интерпретацией.
- Публичный JSON сжимается gzip. Личные API и service worker не меняют правил хранения данных.
- В PDF.js отключена фоновая догрузка всего файла; страницы читаются диапазонами по необходимости. Встроенный PDF остаётся отдельным ленивым модулем.
- Старый `/reader` сохранён для совместимости. Если офлайн-индекс ещё не опубликован, читалка использует прежний полный ответ. Длинные и сложные документы могут потребовать сверки с оригиналом.

## Импорт и запуск

Обычный `docker:up` применяет миграции, восстанавливает старый или новый снимок, собирает приложение и запускает `reference-publish` до веб-сервиса. `--skip-reference` по-прежнему означает явный запуск без восстановления справочника. Если справочник уже заполнен, автоматического замещения нет.

Импорт документов и новой разметки публикует файловые объекты и индекс в своей транзакции. Для одного уже подготовленного официального документа есть `server/import-knowledge.mjs --document knowledge/processed/clinical/<id>.json`; он не требует всего ГРЛС. Исходник должен находиться внутри `knowledge` и совпадать с заявленным хешем.

Разметка `pdfplumber-0.11.9-layout-v4` учитывает фактический межстрочный интервал и отступы, сохраняет отдельные пункты списков и исходные переносы строк внутри ячеек таблиц. Это исправляет разбиение каждого переноса строки в отдельный абзац в PDF с полуторным интервалом. Хеш источника и версия обработчика включены в идентификаторы новых изображений. Неуверенно извлечённые страницы сохраняют изображение источника. Ранее опубликованная разметка не переписывается в runtime: для её улучшения нужен отдельный офлайн-прогон исходных PDF.

Для измерений: `reference:audit`. Отчёт разделяет исходные байты, bytea в БД, вынесенные файлы, уникальные объекты, текст, разметку и физические размеры таблиц. `reference:publish -- --verify` переносит старые встроенные файлы и полностью проверяет уже перенесённые (для CLI нужны административный секрет и доступ к БД).

## Резервные копии

Опубликованный `postgresql-custom-data-v1` остаётся совместимым: он содержит старые встроенные оригиналы; публикация после восстановления переносит их в архив.

Новые экспорты с внешними файлами используют `postgresql-custom-data-v2`: части pg_dump плюс отдельные части `compass-reference-objects-v1`. Инвентарь объектов берётся из того же MVCC-снимка, что дамп, а не из произвольного обхода папок. Каждый объект, часть и весь поток имеют хеш. Экспорт по-прежнему ограничен схемой `knowledge`, без личных данных и секретов.

При восстановлении объекты проверяются до записи ссылок в БД. COPY, проверка числа строк, соответствие полного инвентаря файлов и публикация статуса выполняются в одной транзакции PostgreSQL. Повреждение дампа, поздний сбой потока или несоответствие инвентаря откатывают данные. После неуспешной операции могут остаться только проверенные файлы без ссылок. `db:verify` сверяет строки и хеши объектов.

Экспорт не запускался, новый GitHub Release не создавался. Отдельная внешняя демоверсия не обновлялась.

## Что проверено локально 20 октября 2026

Полный опубликованный снимок занимает 15 922 800 499 байт в сжатом виде; на этом компьютере доступно около 12,7 ГБ. Поэтому перенос всего корпуса и экономия на полном объёме здесь не измерены.

Проверен официальный КР `301_3`, 125 страниц; SHA-256 совпал с манифестом репозитория. PDF 2 148 711 байт и 25 изображений 5 074 652 байта перенесены с сохранением всех хешей. В БД образца больше нет встроенных бинарных оригиналов. Индекс и пять страниц составили 94 796 байта JSON против 1 607 436 байт полного ответа (примерно на 94% меньше до gzip; это объём текста, не замер времени загрузки и не всего корпуса).

Проверены legacy/файловые диапазоны, HEAD/304, строгие версии, полный поиск и отказ runtime в записи. Настоящий pg_dump образца восстановлен в новую временную БД вместе с файлами; несоответствие инвентаря и поздний обрыв откатили все строки. В браузере проверены непрерывное чтение, таблица, поиск и переход на страницу 120, встроенный PDF. Один официальный образец также доступен в основном локальном справочнике; это частичный набор, не полный восстановленный снимок.

Автоматические тесты: `tests/reference-files.test.mjs`. Интеграционная проверка подготовленного официального образца: `scripts/check-reference-files.mjs --source <metadata.json> --layout <layout.json>`; инструмент отказывается работать вне отдельной QA-базы.

После проверки свободного места пользователь отложил загрузку полного снимка. Сейчас полный корпус не скачивается и не восстанавливается; в локальном справочнике остаётся один официальный образец.
