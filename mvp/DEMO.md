# Демоверсия для коллег

Создана по прямому запросу пользователя 17 октября 2026. Сервер — этот компьютер; сайт, PostgreSQL, шлюз доступа и TLS WebSocket-туннель работают в Docker. Использовать только вымышленные данные.

Основной экземпляр остаётся на 127.0.0.1:4174. Стенд `compass-demo` имеет отдельные volume `compass-demo_demo-data`, базу и `.demo-secrets/`. Данные основного экземпляра в него не копируются. У каждого браузера свой тестовый профиль по cookie.

Текущая ссылка находится в `.demo-runtime.env`, код — в `.demo-secrets/demo_access_code`. Эти файлы исключены из Docker-контекста и контроля версий. Ссылку и код передают участникам показа отдельно; ключи БД и шифрования не публикуют.

## Управление

```sh
npm run demo:share
npm run demo:stop
```

Первая команда создаёт недостающие секреты, запускает новый туннель, получает HTTPS origin и обновляет отдельные web/gate. Вторая останавливает весь демостенд, сохраняя его том и ключи. Новый `demo:share` меняет URL; сохранённые записи остаются в БД, но cookie другого hostname не переносится автоматически.

После публикации пользователь попросил оставить этот стенд без изменений. Он использует зафиксированный образ `compass-mvp-web:latest`; основной Compose теперь собирает `compass-mvp-local:latest`, поэтому обычное локальное обновление не меняет публичный код. Не запускать обновление/пересоздание демостенда или туннеля без нового запроса. Если позже публикация изменений будет явно запрошена, сначала собрать отдельный релиз `docker build -t compass-mvp-web:latest .`, затем обновить только `web gate` отдельного Compose-проекта с текущим `.demo-runtime.env`.

Проверки: `npm run test:demo`. Используются отдельные синтетические профили. Общий код не печатается в логах проверки.

## Ограничения

Компьютер, Docker и интернет должны работать; во сне или при закрытом Docker сайт недоступен. Настройки сна компьютера автоматически не менялись. Tunnelmole выдаёт временный адрес; постоянная доступность и сохранение hostname после перезапуска не гарантируются. [Документация сервиса](https://tunnelmole.com/docs/).

HTTPS завершается у сервиса туннеля, затем запрос идёт по отдельному TLS WebSocket-соединению к компьютеру с проверкой сертификата. Оператор туннеля может видеть расшифрованный тестовый трафик. При переданном proxy-признаке HTTP шлюз направляет на HTTPS и отклоняет HTTP-мутации; передавать коллегам только HTTPS-ссылку. Вход защищён общим кодом и восьмичасовым пропуском; перезапуск шлюза сбрасывает пропуска, но не записи PostgreSQL. Туннельный адаптер не содержит SDK, внешней аналитики и request logging.

API не кэшируется. Офлайн-оболочка может оставаться в браузере; без соединения сохранять записи нельзя. Врачебные аккаунты, полноценное восстановление, аудит, медицинский workflow и допуск реальных данных не реализованы. Для постоянной эксплуатации нужен отдельный защищённый хостинг.

Cloudflare Quick Tunnel не смог подключиться к edge в этой сети; localhost.run сменил hostname прямо во время сессии; Serveo закрывал SSH-соединение. Пробные туннели заменены. Текущий маршрут использует Tunnelmole, только к изолированному демошлюзу.
