# История пациента · 24 октября 2026

Персональные ответы имеют `Cache-Control: no-store`. Черновики, страницы и выбранные периоды существуют только в памяти интерфейса. Cookie, роль и ожидаемый аккаунт проверяются так же, как при сохранении.

## Запросы

| GET | Ответ |
| --- | --- |
| `/api/state` | Все схемы лечения и медицинский профиль, наблюдения/отметки за сегодня, legacy doses; без journal. `historyAvailable: true`, `revision` |
| `/api/state?since=<revision>` | При совпадении: `unchanged: true`, без повторной расшифровки/передачи записей |
| `/api/history?kind=notes&limit=20&before=<cursor>&q=<literal>` | Краткие личные заметки: ID, название, даты, версия, `excerpt` до 240 символов. Полного body нет |
| `/api/entries/:id` | Полная собственная запись; для заметки — актуальная редакция. Чужой ID даёт 404 |
| `/api/history?kind=observations&from=YYYY-MM-DD&to=YYYY-MM-DD` | Настроение, сон, опросники выбранного периода |
| `/api/history?kind=doses&from=YYYY-MM-DD&to=YYYY-MM-DD` | Отметки приёма за выбранный период |
| `/api/care/patients/:linkId/history?...` | Период наблюдений/отметок подключённого пациента. Врач, действующая связь и согласия проверяются в транзакции. `kind=notes` запрещён |

Все history-страницы возвращают `{entries, revision, nextCursor, scanned}`. Размер: 1–100, по умолчанию 20. Период наблюдений/отметок — 1–62 календарных дня включительно. Новые параметры валидируются до запроса к БД.

Врачебные заметки/анализы/уведомления продолжают использовать отдельные `/notes` и `/alerts`: их разрешения, привязка к неизменяемой версии и структура не заменены личным history API. В общей карте нет journal; старый личный текст mood скрывается без разрешения на заметки.

## Курсоры и изменения

Keyset: `(saved_at DESC, id DESC)`, без OFFSET. Курсор сохраняет точность PostgreSQL до микросекунд, подписан HMAC с отдельным доменом и связан с владельцем, типом, периодом и поиском. Сменить пациента/фильтр или подделать курсор нельзя.

Миграция `020-history` добавляет счётчик `local_patients.state_revision` и индексы. Триггеры увеличивают счётчик при изменениях entries/legacy doses в той же транзакции. Короткое чтение под SHARE-блокировкой синхронизируется с записью и отзывом. День по Москве входит в ревизию: после полуночи bootstrap обновляется.

Если история изменилась между страницами, ответ — 409 `HISTORY_CHANGED`. Загрузка периода автоматически начинает чтение заново, максимум три попытки. В списке заметок доступен переход к последним записям. Интерфейс не склеивает страницы разных ревизий молча.

Буквальный поиск расшифровывает до 100 кандидатов за запрос на сервере. Курсор указывает последнюю проверенную строку, включая несовпадения; найденные записи после заполнения страницы не пропускаются. Пустая промежуточная страница с `nextCursor` предлагает продолжить поиск. Открытого текстового индекса и внешнего поискового сервиса нет.

## Ограничения

Bootstrap ограничен категориями и сегодняшним днём, но не произвольным общим LIMIT: все действующие и архивные схемы вместе с их версиями сохраняются. При большом числе схем/версий потребуется отдельная оптимизация архива без потери действующего лечения. Период догружается страницами до 100 записей; более 100 страниц требуют выбрать меньший период. Глобальная ревизия пациента может перезапустить чтение при несвязанной записи другого типа — намеренная простота для MVP.

Старый backend без `historyAvailable` обслуживается прежним клиентским путём до обновления схемы/API. Новые API требуют миграцию 020. Presentation prepare применяет её; замороженное внешнее демо не обновляется.

Проверки: `npm test`, `npm run test:integration`, `npm run test:browser`. Последняя команда создаёт отдельную БД, использует только синтетические данные и удаляет БД после завершения. Нужен Chrome на macOS либо установленный Chromium: `npx playwright install --with-deps chromium`. Отчёт и изображения — в игнорируемом `qa/browser/`. Это короткий локальный замер, не проверка производственной ёмкости.
