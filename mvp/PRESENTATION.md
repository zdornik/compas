# Локальный стенд для презентации

Первый запуск на компьютере коллеги, аккаунты, два кабинета и сценарии проверки — [PRESENTATION-HANDOFF.md](PRESENTATION-HANDOFF.md).

Нужны Node 22+ и PostgreSQL **17** с initdb/pg_ctl/psql. Автоматически обнаруживается Homebrew или /usr/lib/postgresql/17/bin, иначе PATH; каталог можно задать PG_BIN. POSIX-управление процессами на Windows не проверено.

```sh
npm ci
npm run build
npm run presentation:prepare
npm run presentation:start
npm run presentation:check
```

Web — http://127.0.0.1:4176/, отдельный PostgreSQL — 127.0.0.1:55434. Основной экземпляр/БД/роли/ключи не используются. Фиксированные порты не должны принадлежать чужим процессам. qa/presentation исключён из Git/Docker context; содержит собственные секреты, кластер и журналы.

Учётные данные — qa/presentation/accounts.json (0600). Основной пациент подключён к врачу, тестовые согласия включены только у него; второй пациент без связи нужен для проверки изоляции. Подготовлены 14 дней вымышленного настроения/сна, обычная и сигнальная заметки. Пароль случайный. Роль определяется общим входом.

prepare повторно сохраняет записи/ключи и применяет новые миграции. start запускает web/worker в фоне, журналы — application.log/postgres.log в каталоге стенда. При завершении одного дочернего процесса контроллер останавливает второй. check проверяет собственные процессы, сохраняет новую вымышленную заметку, ждёт результат до 10 секунд и сверяет миграции/образец. Каждая проба оставляет запись «Проверка готовности стенда»; это намеренная функциональная проверка.

Сборка создаёт build-info.json с fingerprint исходников. API запоминает его при старте, а check сверяет с отдаваемым интерфейсом и ID инстанции. После новой сборки выполнить stop/start: старый процесс со свежей статикой намеренно не проходит проверку готовности. Git revision может быть null в Docker без .git; fingerprint остаётся.

## Небольшой публичный образец

Изначально справочник пуст. Для явного переноса уже имеющегося на этом компьютере официального КР 301_3:

```sh
npm run presentation:reference -- --from-local-reference
```

Credentials/DB_HOST/DB_PORT/DB_NAME применяются только для чтения существующего образца (по умолчанию compass и .local-secrets). Запрашиваются только knowledge.sources/documents/pages/page_assets и известный document ID; персональные таблицы не читаются. Файлы копируются с SHA-256, исходные клинические сведения сохраняются, основная БД не изменяется. Полный корпус не скачивается.

qa/presentation/reference содержит переносимый публичный пакет с контрольными суммами: один PDF, 125 страниц, 25 изображений, без аккаунтов/секретов/препаратов/взаимодействий. Передавать его отдельно, сохраняя ограничения источника; автоматической публикации нет. На втором компьютере подготовить свой стенд, положить этот пакет в тот же подкаталог и выполнить:

```sh
npm run presentation:reference
npm run presentation:check
```

## Остановка и сброс

```sh
npm run presentation:stop
npm run presentation:reset
npm run presentation:start
npm run presentation:check
```

stop проверяет маркеры собственных процессов и останавливает только их и собственный PostgreSQL. Данные остаются. reset удаляет/создаёт только БД с проверенным именем внутри собственного кластера, возвращает вымышленные записи и staged-образец. Ключи сохраняются, пароли аккаунтов меняются; после сброса прочитать новый accounts.json. Это сброс одноразового стенда, не резервное восстановление реальной персональной БД.

Не переносить каталог PostgreSQL между платформами как бэкап. Для новой подготовки нужны код, свежие собственные секреты и маленький публичный reference-пакет. Незавершённая первичная подготовка требует reset этого стенда.

Показ: пациент → дневник/новая заметка → врач/подключённый пациент/записи → тестовое уведомление. Маркер [TEST:elevated] выбирает тестовый сценарий. Для приёма пациент запрашивает будущее время, врач подтверждает в календаре. Внешней нейросети/уведомлений нет; результат подписан как заглушка.

## Проверка истории и браузера, 24 октября

Новая миграция 020 применяется через `presentation:prepare`; после пересборки перезапустите web/worker, чтобы preflight подтвердил совпадение API и интерфейса. Данные presentation при prepare не сбрасываются. Основная БД и замороженное внешнее демо не обновляются этой командой.

`npm run test:browser` проверяет свежую синтетическую БД отдельно от presentation: 500 длинных заметок, год наблюдений, старую действующую схему, вход двух ролей, источник/уведомление/принятие, сохранность черновика, отзыв и мобильную ширину. Автоматический запуск сам удаляет созданную БД. Короткие измерения двух окон не заменяют 20-минутную репетицию и восстановление персонального бэкапа.

## Сохранение комплекта и резервная запись

```sh
npm run presentation:backup
npm run presentation:restore-check
npm run test:rehearsal
npx playwright install ffmpeg
npm run presentation:video
```

Последние три проверки выполняются на собственных свежих QA-БД. Для показа при отказе сервера сохраните `qa/video/index.html`, `patient.webm` и `doctor.webm` вместе и откройте HTML в обычном браузере: сеть/API не нужны. Воспроизведение по умолчанию замедлено вдвое, чтобы читать оба кабинета. Запись без звука; это резерв демонстрации функций, а не запись полного выступления.

Бэкап: отдельный `.cpbak` и раздельно сохранённый `qa/presentation/secrets/backup_key`. Весь каталог PostgreSQL как переносимый бэкап не используется. Правила восстановления — BACKUP.md; готовый сценарий выступления — DEMO-SCRIPT.md.
