# Приватный бэкап и восстановление · 24 октября 2026, МСК

Реализован зашифрованный комплект текущей БД, ключа данных и используемых файлов справочника. Операционные команды работают с собственным синтетическим presentation-кластером; основной экземпляр не заменяют. Это отдельный механизм от публичного reference export.

## Команды

```sh
npm run presentation:backup
npm run presentation:restore-check
```

Первая команда сохраняет новый файл `backups/presentation/*.cpbak`, не перезаписывая предыдущие. Последний путь записан в `qa/presentation/last-backup.json`. Вторая восстанавливает его в новую случайную `compass_journal_qa_*`, проверяет содержимое/доступ/worker и удаляет только созданную проверочную БД и временный каталог. Конкретный комплект: `npm run presentation:restore-check -- /absolute/path/backup.cpbak`.

Нужен уже подготовленный PostgreSQL 17-кластер Компаса с собственными паролями ролей и утилитами `pg_dump`, `pg_restore`, `psql` версии 17. Локально используется Homebrew/PATH либо `PG_BIN`. В CI закреплён клиент 17 из [официального репозитория PostgreSQL](https://www.postgresql.org/download/linux/ubuntu/); само выполнение GitHub Actions ещё не подтверждено.

## Содержимое и защита

- MVCC-снимок `pg_dump --format=custom` со схемой, персональными записями, версиями, согласиями, связями, сообщениями, приёмами, очередью/результатами и knowledge. Активные `app_sessions` исключены: старые cookie после восстановления не действуют.
- Ключ данных находится **внутри зашифрованного комплекта**. Пароли PostgreSQL и файл логинов presentation не включаются. Для расшифровки нужен другой, независимый 256-битный `qa/presentation/secrets/backup_key`.
- Внешняя оболочка — AES-256-GCM со случайным IV и аутентифицированным заголовком. Файлы имеют SHA-256 и размеры, манифест зашифрован. Комплект и ключ создаются с правами 0600, временные каталоги — 0700.
- Список PDF/изображений берётся из того же MVCC-снимка. На время копирования удерживается совместная блокировка публикации справочника; неизменяемые объекты проверяются по хешам. Неиспользуемые файлы архива не копируются.
- Текущий локальный инструмент ограничен БД до 1 ГиБ и содержимым комплекта до 1 ГиБ. Это намеренный предел для небольшого стенда при ограниченном месте; поддержка полного опубликованного корпуса здесь не заявляется.

## Что делает восстановление

Полностью проверяет GCM, инвентарь, пути, размеры и хеши **до создания БД**. При неверном ключе/изменённом комплекте PostgreSQL не затрагивается. Существующая БД запрещена как цель; нет флага обхода этого запрета. Ошибка удаляет только новую проверочную копию и её временные файлы.

`pg_restore` работает одной транзакцией и сохраняет владельцев/ACL. Опция `--no-owner` здесь не используется: она могла бы сделать владельцем функций ограниченного worker административную роль. После восстановления сравниваются количества всех таблиц, миграции, RLS-флаги и владельцы/ACL таблиц/функций.

Потерянные worker-аренды ограждаются: токен очищается, задания с оставшимися попытками становятся `retry_wait`, четвёртая исчерпанная попытка — `failed`, завершённые/отменённые задания сохраняются. Новая аренда увеличивает счётчик, прежний токен больше не читает исходник.

Восстановленный комплект не запускает публичный web автоматически. Для настоящего переноса нужен подготовленный приватный экземпляр, проверенный код, свои пароли ролей и отдельно доставленный `backup_key`.

## Проверено

На presentation-наборе: 7 756 177 байт, 58 таблиц и 26 объектов; восстановление и функциональные проверки — 1 304 мс в одной локальной пробе. Вход обеих ролей, расшифровка исходника, действующая связь, запрет чужому пациенту, новое сохранение, результат/уведомление и ограничение прямого SQL-доступа worker прошли. Это единичный результат, не RTO/SLA.

Fresh-DB интеграция дополнительно проверяет сохранение двух версий заметки, сообщения и подтверждённого приёма; отсутствие старых сессий, восстановление незавершённого задания, отказ старому lease-токену, исчерпанные попытки, неверный ключ и отказ перезаписать существующую БД. Автоматические команды: `npm test`, `npm run test:backup`; общий `test:integration` включает этот сценарий.

Сводка — `qa/backup/report.json`. Комплекты, ключи и проверочные данные исключены из Git/Docker context. Сейчас бэкап и его ключ физически находятся на этом компьютере. Защита от потери всего компьютера требует отдельной копии комплекта и раздельно сохранённого ключа; сетевое хранилище, расписание и политика хранения этим изменением не подключены.
