# Готовая PostgreSQL-база справочника

`reference-snapshot.json` описывает один снимок `pg_dump` формата custom из схемы `knowledge` PostgreSQL 17. Большой бинарный снимок разделён на последовательные части по 512 МиБ и размещён в приватном GitHub-релизе; исходные таблицы Excel/CSV и JSON-архивы не являются способом установки.

Снимок от 19 октября 2026 года: 15 922 800 499 байт (15,9 ГБ), 30 частей и 33 справочные таблицы. В нём 33 клинрека, 2 607 файлов инструкций, 126 861 регистрационная запись, 295 183 записи взаимодействий лекарств и 8 268 взаимодействий с заболеваниями. Полный SHA-256, количества строк и версии миграций закреплены в манифесте.

Внутри БД сохранены:

- оригинальные клинреки и инструкции, PDF/изображения, текст и разметка страниц;
- регистрационные записи ГРЛС, связи ЕСКЛП/СМНН/КЛП и исходные коды;
- словари МНН ЕАЭС/НСИ, языковые подписи, проверенные составы и зависимости компонентов;
- исходные пары взаимодействий лекарств и лекарств с заболеваниями, МКБ и явные связи диагнозов;
- источники, версии, хеши, ограничения использования и статусы проверки;
- индексы и подготовленные каталоги для быстрого поиска.

Схему создают миграции из репозитория; снимок восстанавливает готовые данные. Единственная исключённая служебная строка — `knowledge.catalog_state`: её счётчики и статус публикации пересчитываются после восстановления. Это не повторный импорт исходников. Большие объекты PostgreSQL вне схемы и всё пространство `public` в дамп не попадают. Аккаунтов, сессий, ключей, сообщений и записей пациентов в нём нет.

## Автоматическая установка

```sh
npm run docker:up
```

Установка использует авторизованный GitHub CLI для приватных файлов. Проверяются отдельные SHA-256/размеры, порядок частей, полный SHA-256 потока, перечень таблиц, версия миграций и числа восстановленных строк. Данные загружаются в одной транзакции; существующая заполненная справочная база сохраняется. Приложение запускается после успешного восстановления.

На новом компьютере предусмотрите около 40 ГБ свободного места для PostgreSQL, индексов и временных данных. Загрузчик хранит одну часть, а не вторую полную копию архива.

## Офлайн-восстановление

Если части релиза уже скачаны в одну папку:

```sh
npm run db:restore -- --local-parts /absolute/path/to/parts
```

PostgreSQL и миграции должны быть подготовлены. Части в указанной папке не удаляются. Тот же вариант можно передать полному запуску:

```sh
npm run docker:up -- --local-parts /absolute/path/to/parts
```

## Проверка и обновление снимка

`npm run db:verify` сравнивает установленную базу с манифестом. В `scripts/check-reference-restore.mjs` есть проверка переноса на отдельном Docker-проекте с вымышленной тестовой средой и настоящими публичными справочными записями. Она не переносит медицинские профили и не изменяет рабочую БД.

Экспорт администратором выполняется через `npm run db:export`. Он фиксирует согласованный MVCC-снимок и выгружает только `knowledge`, без PostgreSQL large objects и пользовательских таблиц. Части загружаются в черновик приватного релиза, подтверждаются серверными SHA-256 GitHub и удаляются из временного каталога. Готовый манифест публикуется только после успешного завершения всего `pg_dump`. Существующий релиз не перезаписывается. Для следующей версии задайте новый тег, например `npm run db:export -- --release reference-db-2026-10-20`.

Права на данные остаются у исходных источников. Снимок не является клиническим допуском и не расширяет неполное покрытие взаимодействий. Атрибуция и исходные лицензии — в `knowledge.sources`, [KNOWLEDGE.md](../KNOWLEDGE.md) и `knowledge/licenses`.
