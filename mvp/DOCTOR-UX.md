# Текущее состояние

Кодовый сценарий подключения, назначений и профиля реализован в ConnectedCare; актуальное описание — в README.md, SECURITY.md и KNOWLEDGE.md. Ниже сохранена исходная UX-концепция; вымышленные карты удалены из основного интерфейса, календарь и переписка пока не подключены к медицинским записям.

# Компас · интерфейс врача

18 октября 2026. Продолжение действующего пациентского сайта, по требованиям чата «Создать MVP интерфейс».

Вход `/` предлагает роль; `/#doctor` открывает кабинет врача, `/#patient` — существующий пациентский интерфейс. «Сменить роль» находится в боковой панели, на телефоне — справа вверху. URL не является авторизацией. Выбор роли не предоставляет права чтения базы.

## Экраны

- Обзор: поводы обратить внимание, новые записи, расписание дня.
- Пациенты: поиск имени и фильтры, переход в карту.
- Медкарта: динамика настроения за 7/14 дней или текущий месяц, сон, регулярность отметок препаратов, примеры результатов опросников и события. Отсутствие данных показано отдельно.
- Лечение: расположение назначения, этапов титрации, регулярности отметок и цикла наблюдения.
- Дневник: исходные вымышленные записи, фильтры состояния/сна и вход к будущей сводке.
- Документы: примеры карточек обследований и выписок.
- О пациенте: сведения о здоровье, структура доступа и смены врача, место для проверки взаимодействий.
- Календарь: день/неделя, переход по датам, открытие карты пациента из приёма. Вымышленные приёмы заданы на 18 октября 2026, время московское.
- Справочник: структура рекомендаций, инструкций и взаимодействий, фильтрация названий разделов.
- Сообщения: структура диалогов без сообщений и отправки.

## Граница прототипа

Врачебные страницы используют самостоятельные fixtures из `src/DoctorWorkspace.jsx`. Они не получают данные пациентского API, не сохраняют врачебные записи и не отправляют запросы в медицинские сервисы. В браузерные хранилища ничего не добавлено. Фильтры и навигация существуют только для просмотра дизайна.

Назначения, приглашения, загрузка документов, запись на приём, периодичность опросников, передача доступа, сообщения, медицинские источники, взаимодействия и AI-сводки пока не подключены. Их кнопки открывают пояснительные макеты без имитации успешного действия. Реальная реализация и проверки доступа остаются в TASKS.md.

Пациентские страницы и состояние сохранены; при смене роли закрываются открытые окна. Локальная база и опубликованный внешний демостенд не меняют структуру или данные из-за этого интерфейса.

## Рабочие сценарии демо

Карты вымышленных пациентов теперь позволяют создавать и менять ручные схемы приёма, раскрывать титрацию, проверять схему перед сохранением и завершать её с сохранением истории версий. Используется общий пациентский редактор без автоматического подбора доз. Подписания рецепта и отправки пациенту нет. Данные врача в этой итерации живут до перезагрузки, не читают cookie-профиль пациента и не записываются в его лечение.

Графики и календарь получают один набор вымышленных наблюдений на пациента. Пропущенные дни остаются пропусками. Среднее вычисляется только для длительности сна и только по записям; настроение остаётся отдельными категориями и точками. Можно открыть конкретный день, прочитать исходную запись, переключить тип записей и период. Приёмы создаются в демо-памяти, с проверкой пересечений по времени, без уведомлений.

Используются общие CalendarMotion, DiaryCalendar, DatePicker, TimeWheel, MedicationEditor; SlidingTabs объединяет поведение переключателей. Реальные страницы приложения не анимируются. Reduced motion сохраняется.

Дневник также показывает вымышленные общие личные записи с поиском и просмотр PHQ-9/GAD-7 с исходными ответами. Формы и расчёт берутся из существующего проверенного модуля пациента, без изменения шкал.
