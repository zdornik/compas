# Сценарий показа Компаса · 7–9 минут

Материал для заказчика/инвестора. Использовать только presentation-аккаунты; перед показом выполнить preflight. Это сценарий выступления, не готовый слайд-дек.

| Время | Действие | Реплика и смысл |
| --- | --- | --- |
| 0:00–0:45 | Два кабинета рядом | «Компас помогает сохранять наблюдения между приёмами и передавать врачу контекст с разрешения пациента». |
| 0:45–1:30 | Пациент → Врач, показать подключение и отдельные разрешения | «Выбор роли не даёт доступ к карте. Пациент подтверждает конкретного врача; личные заметки разрешает отдельно». В подготовленном наборе связь уже одобрена — сказать это прямо. |
| 1:30–2:45 | Дневник, новая заметка, сохранить | «Запись сохраняется в БД. История приходит страницами, полная запись открывается отдельно». Показывать вымышленный текст. |
| 2:45–4:15 | Врач, заметки/уведомление/исходник/принятие | «Сейчас анализ выполняет локальная заглушка. Явный TEST-маркер выбирает тестовый сигнал; медицинскую классификацию мы здесь не демонстрируем». Открыть точную версию и принять уведомление. Это действие врача в приложении, не подтверждение нормализации состояния. |
| 4:15–5:45 | Пациент запрашивает приём, врач подтверждает | «Пациент предлагает время, врач подтверждает. До подтверждения слот не занят». Затем показать прямое назначение второго времени врачом. |
| 5:45–6:30 | Врач → Дневник/прошлая неделя, либо официальный образец КР | Показать реальные сохранённые наблюдения за выбранный период. Для КР назвать источник; сказать, что в стенде один образец, а не весь каталог. |
| 6:30–7:15 | Отзыв доступа, либо заранее записанный пример отказа | «После отзыва последующие чтения закрываются. Черновик при сбое сети остаётся в форме». Не менять права до завершения остальных сцен. |
| 7:15–8:15 | Схема и проверенные результаты | «React → API → PostgreSQL; отдельный обработчик заметок и файловый архив. Бэкап восстановлен в другой БД. Двадцатиминутный локальный прогон выполнен». Не выдавать это за производственную ёмкость или медицинский SLA. |
| 8:15–9:00 | Следующий эксперимент и запрос | Согласовать с заказчиком реальный процесс реагирования, критерии качества анализа и ограниченный следующий эксперимент. Не обещать клинический запуск по одному показу. |

Пример сигнальной заметки: `[TEST:elevated] Это вымышленная запись для демонстрации уведомления`. Нельзя получать тестовый сигнал из настоящего описания самочувствия.

До выступления: проверить питание/масштаб экрана, вход обеих ролей, выполнение worker, ближайшие свободные тестовые времена, файл бэкапа и отдельный ключ. Выполнить функциональную проверку заранее — она оставляет тестовую запись в дневнике.

При отказе сервера открыть `qa/video/index.html` с двумя лежащими рядом WebM. Запись без звука; общий плеер воспроизводит оба кабинета с замедлением для чтения. Это резерв демонстрации функций длительностью около минуты при 0,5×, не видеозапись всего выступления.
