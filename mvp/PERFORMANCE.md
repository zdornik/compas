# Размер и нагрузка прототипа

Исторические замеры первой интернет-версии от 17 октября 2026. После добавления лечения размеры изменились; повторный профиль текущего релиза не выполнялся. Это локальные инженерные замеры, не нагрузочная сертификация и не проверка смартфонов.

## Что скачивает браузер

| Ресурс | Исходный размер | Brotli при передаче |
|---|---:|---:|
| JavaScript | 343 927 Б | 94 818 Б |
| CSS | 90 512 Б | 15 570 Б |
| Вся уникальная оболочка с используемыми изображениями, манифестом и иконками | 1 560 930 Б | 1 236 009 Б |

Сжатие готовится при сборке, а не вычисляется сервером на каждый запрос. HTTP-ответ JS проверен: Content-Encoding=br, Content-Length=94818. Картинки уже WebP/PNG, повторно не сжимаются. Число файлов относится к первой версии; отвергнутые v3/v5, миниатюры и старые рендеры впоследствии удалены. Используются системные шрифты.

1,24 МБ — сумма уникальных ресурсов оболочки, без персональных ответов API и HTTP/TLS overhead. Первый запуск может передать больше из-за отдельного заполнения офлайн-кэша. Это не размер Docker-образа, всей папки разработки или памяти браузера.

## Где выполняются анимации

На устройстве посетителя. Перемещение маскота, кнопок и окон использует CSS transform/opacity и браузерный compositor. Цвет контуров вычисляется WebGL shader на GPU из исходной 971×1619 текстуры, с Canvas2D fallback при отключённом WebGL. Внутренняя текстура не размывается и не уменьшается до миниатюры.

Постоянного перерисовывания цветных пикселей в покое нет. Кадры нужны при смене палитры/геометрии, затем цикл останавливается. Скрытые страницы и вкладки приостанавливают перерисовку. Дыхание маскота — небольшое CSS-перемещение. Reduced motion отключает переходы. Видеопоток, серверный рендер кадров и передача координат каждого движения отсутствуют.

Браузерный замер 1280×720: за 46,07 с на главной главный поток был занят 55,56 мс, JavaScript — 0,37 мс. Это около 0,12% времени одного ядра по TaskDuration. JS heap около 7,9 МиБ; это **не вся память вкладки**: GPU textures, native buffers, браузер и compositor сюда не входят.

Предельный искусственный ввод 12 смен Home/End за 0,35 с занял 174 мс главного потока, включая автоматизацию/обработку ввода, и 46,5 мс выполнения JS. Кратковременная нагрузка при быстрых движениях выше покоя. Эти данные не измеряют GPU time, FPS, батарею или нагрев реального телефона; старые смартфоны и Canvas2D fallback нужно проверять отдельно.

## Что достаётся серверу

Раздача файлов, проверка cookie/доступа, валидация, SQL, шифрование и сохранение. Анимации тысячи посетителей не превращаются в тысячу анимаций на сервере.

Снимок Docker после проверки интернет-API: демошлюз около 21 МиБ RAM, web/API около 25 МиБ, PostgreSQL около 29 МиБ, TLS WebSocket-туннель около 21 МиБ; суммарно около 97 МиБ контейнеров. Docker Desktop VM, ОС, дисковый кэш и локальный основной экземпляр в эту сумму не входят. Нагрузка базы периодически выше нуля из-за служебных процессов. Временный транспорт также добавляет служебный объём и обработку сообщений к раздаче файлов.

Локальная синтетическая проверка: 80 чтений маленького /api/state, параллелизм 8, 143 мс суммарно, средний запрос 13,95 мс, p95 39,83 мс. Это loopback и небольшой набор записей, без интернет-туннеля; такой результат нельзя переносить на тысячи пользователей и большие дневники.

Для нескольких коллег основными ограничениями будут исходящая скорость компьютера и бесплатного туннеля. При росте нужны постоянный хостинг, CDN для статики, управляемая БД, лимиты/пагинация больших дневников и нагрузочные тесты реалистичного сценария. Например, 100 новых посетителей потребуют около 124 МБ уникальной статики, независимо от того, сколько раз они двигают ползунок после загрузки.
