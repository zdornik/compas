# Компас · локальный MVP пациента и интерфейс врача

Адаптивный сайт/PWA в согласованном стиле v7: маскот, чёткие неглубокие контуры и семь палитр от синего через светлый зелёный к мягкому закатному золоту. Текущий вариант запускается в Docker и сохраняет данные в PostgreSQL.

## Выбор роли и кабинет врача

На входе можно выбрать «Я пациент» / «Я врач». У ролей отдельные cookie-профили в одном браузере. Пациент получает постоянный код в разделе «Врач»; специалист запрашивает подключение, а пациент подтверждает доступ. В обзоре отображаются подключённые пациенты. Врач видит доступные дневники, назначает схемы в «Лечение» пациента и уточняет принимаемую терапию и хронические диагнозы с историей правок. Производственная проверка личности и квалификации врача пока не подключена. Переписка и запись на приём остаются макетом. Внешняя демоверсия не обновляется.

Справочник содержит 33 КР с кодами F00–F99, регистрационную выгрузку ГРЛС и 1 922 файла инструкций психиатрического отбора. Документы доступны непрерывным текстом и в исходном PDF с навигацией, поиском и выделением. В корпус OpenMRS/DDInter импортированы 295 183 прямые пары лекарств и 8 268 записей о заболеваниях; подтверждены 40 связей русских МНН с английскими ID, остальное явно отмечается как неполное покрытие. Официальный словарь МНН ЕАЭС содержит 9 578 пар русских/английских названий для поиска, отдельно от подтверждённых ID взаимодействий. Каталог МКБ-10 содержит 14 641 код, принимает разговорные названия и показывает обычные взрослые диагнозы выше узких вариантов. Окна выбора и списки плавно меняют размеры. Источники, версии и ограничения — [KNOWLEDGE.md](KNOWLEDGE.md). Отсутствие пары или совпадения не означает совместимость.

## Что работает

- Настроение: непрерывная шкала, уточняющие слова и факторы. Главная отмечает сегодня; прошлые дни выбираются в дневнике. Редактирование не создаёт дубль.
- Общая палитра всех разделов, бумаги дневника, кнопок, календарей и форм следует настроению; при закрытии несохранённого выбора возвращается сохранённый цвет. Прошлая отметка не меняет сегодняшний цвет.
- Дневник: список в духе Notes, поиск, большие тексты до 20 000 символов, редактирование, собственный календарь.
- Меню «+» дневника объединяет настроение, сон и опросники; для личной записи есть отдельная кнопка. Календарь плавно меняет высоту при переключении недели/месяца, перелистывает периоды и сохраняет выбранный период при смене режима.
- Сон: прокручиваемые колёсики часов/минут, дата и качество отдыха.
- PHQ-9 и GAD-7: полные русские формы, подсчёт на клиенте и повторная проверка сервером, отдельные результаты в дневнике. Источники и ограничения — [ASSESSMENTS.md](ASSESSMENTS.md).
- Результат читается независимо от цвета настроения: тёмный текст, светлая подложка балла, спокойная поддерживающая подсказка, раскрывающиеся ответы и отдельная ссылка на исходную форму.
- Лечение: ручные схемы препаратов, мг/мкг, время приёма, количество, связь с едой, редактирование и архив. Титрация раскрывается плавно: длительность, дозировка и количество для каждого этапа. На главной — предстоящие приёмы, в лечении — история и исправление отметок.
- Врач: подключение по коду с согласием пациента, карта и дневники, назначения с проверкой исходников, редактирование медицинского профиля и история. Переписка и запись на приём пока не подключены.
- Страницы переключаются без движения. Выбор опросника открывается компактно; после выбора окно плавно расширяется, во время вопросов сохраняет размер и плавно переходит к результату. Фон маскота продолжается за заголовком и кнопками. Reduced motion учитывается.
- Маскот остаётся над вопросами, прокручивается вместе с содержимым и плавно возвращается рядом с баллом. Соотношение маскота и контуров одинаковое с редактором настроения; фон продолжается за исходную картинку без видимого стыка.

## Docker

```sh
npm run docker:up
```

Команда создаёт локальные случайные секреты, сохраняя существующие, собирает приложение и запускает сервер и базу; отдельный одноразовый контейнер применяет миграцию до запуска сервера. Сайт: http://127.0.0.1:4174/ . PostgreSQL не публикует порт на компьютере. Приложение публикует только loopback 4174. Образ приложения работает от пользователя node с файловой системой только для чтения.

Локальная разработка использует отдельный образ `compass-mvp-local:latest`. Опубликованный стенд продолжает использовать зафиксированный `compass-mvp-web:latest`; локальные сборки его не заменяют и демоконтейнеры не пересоздают. Обновление интернет-версии — только по отдельному запросу пользователя.

```sh
npm run docker:stop
```

Остановка не удаляет данные. Они находятся в именованном томе `compass-mvp_compass-data`; ключи — отдельно в `.local-secrets/`, исключённой из сборки и контроля версий. **Не удалять том, папку ключей и cookie профиля для обычного обновления.** Без ключа содержимое записей не восстановить. Для обновления кода снова выполнить `npm run docker:up`.

Сохранённые записи переживают обновление страницы и перезапуск контейнеров. Несохранённые черновики и ответы в незавершённом опроснике пока остаются в памяти формы. Доступ локального профиля привязан к HttpOnly/SameSite cookie этого браузера на 30 дней; другой браузер открывает отдельный профиль. Входа по аккаунту и восстановления доступа пока нет. Это ограничение локального прототипа, не система идентификации пациентов.

В базе сохраняются дневник, настроение, сон, полные результаты опросников схемы препаратов, версии схем и отметки приёмов. Форма сообщает об успехе только после ответа базы. При недоступности сервера сохранение не имитируется, введённый текст остаётся в форме.

Открытые вкладки обновляют сохранённые записи после изменений и при возвращении в окно. Между вкладками передаётся только сигнал обновления без текста, ответов и идентификаторов. Несохранённые формы сохраняются в памяти; для схем препаратов и отметок приёмов проверяются ревизии; при конфликте предлагается перечитать актуальную схему.

## Проверки

```sh
npm run build
npm test
npm run test:sites
npm run test:api
```

Последняя команда требует работающего Docker и использует только синтетические данные двух отдельных тестовых профилей. Проверяет сохранение, повторное редактирование без дубля, изоляцию профилей, CSRF/Origin, серверный подсчёт и независимые статусы препаратов.

`npm start` без переменных подключения обслуживает только статическую сборку, сохранение в этом режиме отключено. Для полноценного MVP использовать Docker. Шаблон Sites сохранён, но статическая публикация сама по себе не переносит локальную базу и API.

## Стек и безопасность

React 19.2, Vite 6.4.4, CSS-токены, Phosphor, Node 24, node-postgres, PostgreSQL 17. Один сервер обслуживает frontend и API одного origin. Запросы параметризованы; runtime-роль не владелец БД, RLS ограничивает записи текущим профилем. Тексты и ответы зашифрованы AES-256-GCM с привязкой к профилю и записи. Cookie — HttpOnly/SameSite; мутации требуют Origin и CSRF-токен. API не кэшируется, в браузерное хранилище медицинские данные не записываются.

**Использовать только вымышленные данные.** Локальная cookie-сессия, шифрование и контейнеры не означают готовность медицинского сервиса. До реальных пациентов нужны полноценная идентификация и восстановление, управление ключами, бэкапы и восстановление, роли врача, аудит, проверка безопасности и клинический процесс. По прямому запросу пользователя отдельно запущена интернет-демоверсия для коллег с HTTPS и кодом входа; первичная локальная база в неё не переносится. Управление и ограничения — [DEMO.md](DEMO.md), измерения — [PERFORMANCE.md](PERFORMANCE.md).

## PWA и дальнейшие функции

Есть манифест, иконки и кэш только публичной оболочки. API и записи service worker не кэширует. Запись офлайн пока недоступна. Для установки на телефон потребуется отдельный HTTPS-домен; 127.0.0.1 компьютера с телефона недоступен. Физические устройства и push ещё не проверены.

Пока отсутствуют медицинская карта, создание и подтверждение назначений врачом, проверка медицинской корректности схем, чат, календарь врача, смена врача с отзывом прав, профиль заболеваний, взаимодействия лекарств, AI-анализ, Apple Health и фоновые уведомления. В интерфейсе нет имитации их успешной работы.

### Обновление врача и справочника, 18 октября

Локальный кабинет врача (#doctor) использует отдельные вымышленные карты. Работают ручные схемы приёма с титрацией, проверкой перед сохранением, версиями/завершением; календарь приёмов проверяет пересечения. Эти изменения хранятся в памяти до перезагрузки, не доставляются пациенту. Дневники состояния, сна, общих записей и опросников доступны для просмотра с графиками и календарём. Общие элементы взаимодействия перенесены из пациентского кабинета.

Справочник содержит настоящие официальные документы. Инструкции и КР открываются непрерывным текстом или в локальном PDF-просмотрщике с поиском, масштабом, навигацией и выделением. Счётчики различают МНН/составы, регистрации и файлы; по умолчанию показан психиатрический отбор и сначала готовые инструкции. Подробности источников и ошибок — KNOWLEDGE.md. Реальное связывание врача с пациентом и медицинская эксплуатация требуют отдельного этапа.

## Учётные записи и общение

Вход и регистрация пациента/врача работают с отдельными локальными аккаунтами. Вводные страницы собирают имя, фамилию, возраст пациента, необязательные препараты/диагнозы и явные согласия. Исходные локальные профили можно открыть без регистрации; при создании аккаунта их записи автоматически не переносятся. После выхода прежний локальный профиль сохраняется отдельно.

Тексты личного дневника закрыты врачу по умолчанию. Обработка и чтение подключённым врачом включаются отдельными разрешениями и отзываются в настройках. Дополнительного AI-анализа нет. Чат сохраняет зашифрованные сообщения между сторонами активного подтверждённого подключения, обновляет открытую переписку и хранит черновики только в памяти. Вложения, фоновые уведомления и отметки прочтения пока не подключены.

Это исследовательская регистрация: подтверждение почты/квалификации врача, восстановление пароля и юридическая подготовка клинического сервиса остаются отдельными задачами. Проверки: `npm test`, `node scripts/check-auth.mjs`, `node scripts/check-care-chat.mjs`; последние два используют новые синтетические профили и не обращаются к данным текущего браузерного пациента.
