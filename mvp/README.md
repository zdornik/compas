# Компас · локальное приложение пациента и врача

Адаптивный сайт/PWA с регистрацией, отдельными ролями, дневниками и общим медицинским справочником. Данные сохраняются в PostgreSQL. Это исследовательский прототип для вымышленных данных.

## Запуск после скачивания из GitHub

Нужны Docker с Compose, Node.js 22+ и GitHub CLI. Для приватного снимка БД войдите в GitHub CLI под аккаунтом с доступом к `zdornik/compas`:

```sh
gh auth login
npm run docker:up
```

Команда создаёт новые локальные ключи, запускает PostgreSQL, применяет миграции, восстанавливает готовую справочную базу и собирает приложение. Открыть: http://127.0.0.1:4174/.

На первом запуске загружается большой снимок PostgreSQL. Исходные Excel/CSV/JSON и повторный разбор PDF не нужны. Части снимка находятся в [релизе базы](https://github.com/zdornik/compas/releases/tag/reference-db-2026-10-19); их порядок, размеры и SHA-256 закреплены в [манифесте](database/reference-snapshot.json). Для проверки и загрузки требуется Интернет; ориентир для установки — 40 ГБ свободного места. Загруженные части удаляются из временного каталога по мере передачи в PostgreSQL.

Уже заполненная база автоматически не перезаписывается. Существующие локальные ключи сохраняются. После новой установки создайте свои аккаунты в интерфейсе: пароли, личные записи и подключения с другого компьютера в справочный снимок не входят.

## Возможности

- Вход и регистрация пациента/врача, вводные страницы и отдельные разрешения на обработку и доступ к текстам дневника.
- Настроение, сон, личные записи, PHQ-9/GAD-7, история и календарь. Опросники не устанавливают диагноз.
- Ручные схемы терапии, титрация, напоминания, отметки приёмов и история изменений.
- Подключение врача по постоянному коду пациента с отдельным подтверждением. Сервер проверяет активное подключение при каждом обращении к карте и переписке.
- Назначение врачом с передачей в лечение пациента, уточнение принимаемых препаратов и хронических диагнозов.
- Зашифрованный чат. Тексты личного дневника закрыты врачу по умолчанию.
- Клинреки и инструкции: непрерывный текст, содержание, поиск и исходный PDF с выделением и масштабом. Регистрационные записи и файлы инструкций считаются отдельно.
- Общая PostgreSQL-база ГРЛС, ЕСКЛП, словарей МНН ЕАЭС/НСИ, МКБ и исходных взаимодействий. Поиск работает по торговым названиям, МНН, официальным языковым вариантам и кодам.

В справочнике 33 документа текущего отбора по кодам F. Это полнота скачивания выбранной коллекции, а не полный охват психиатрической практики; расширение по темам и статусам источников остаётся в очереди. Актуальные количества препаратов, переводов и взаимодействий приложение читает из БД. Полный состав и ID источника проверяются отдельно от наличия английской подписи. Отсутствие пары не означает безопасность сочетания.

## Готовая база

[Описание снимка и восстановления](database/README.md). Миграции и индексы находятся в `docker/migrations`; runtime получает только чтение справочника. Оригинальные PDF и изображения страниц находятся внутри БД, вместе с контрольными суммами, версиями и происхождением.

Снимок предназначен для некоммерческого исследования. Лицензии и ограничения источников сохранены в БД, [KNOWLEDGE.md](KNOWLEDGE.md) и `knowledge/licenses`.

## Проверки

```sh
npm test
node scripts/check-reference-restore.mjs
npm run db:verify
```

Вторая команда проверяет перенос на отдельном временном Docker-проекте с новым хранилищем: реальные публичные документы, PDF, разметка, языковые соответствия и взаимодействия. Повреждённая часть должна быть отклонена; записи пациентов не копируются. `db:verify` сравнивает числа строк со снимком; после последующих импортов данные могут отличаться от зафиксированной версии.

Внешняя демоверсия из `compose.demo.yaml` остаётся отдельной и не обновляется этими командами. Проверка квалификации врача, подтверждение почты, восстановление пароля, фоновые уведомления, AI-анализ и запись на приём остаются отдельными задачами.

## Заметки и тестовая обработка

Заметки имеют зашифрованные версии, защиту от конфликтов, очередь и уведомления врачу. По явному решению пользователя анализ пока выполняет локальная заглушка: внешних вызовов и реальной оценки состояния нет. Согласия, запуск без справочника и проверка — [JOURNAL.md](JOURNAL.md), контракт — [journal.openapi.json](journal.openapi.json).
# Запись на приём

Врач назначает приём в «Календаре», пациент отправляет запрос в разделе «Врач → Приёмы и запросы». Запрос подтверждается или отклоняется врачом. Нужны зарегистрированные аккаунты и подтверждённое подключение. Время показано по Москве, запись сохраняется в PostgreSQL; пересечение подтверждённых приёмов блокируется базой. API, модель данных и проверки описаны в [APPOINTMENTS.md](APPOINTMENTS.md).


Публичные PDF и изображения справочника теперь хранятся в проверяемом файловом архиве; текст загружается по мере чтения. Устройство, миграция, совместимость снимков и локальные ограничения описаны в [REFERENCE-FILES.md](REFERENCE-FILES.md). Для резервной копии нужно сохранять и БД, и файлы: новый экспорт v2 включает обе части. На текущем локальном запуске доступен один официальный образец КР; полный опубликованный снимок требует больше свободного места на диске.
