# Компас · MVP интерфейса пациента

Работающий адаптивный прототип сайта/PWA. Основной экран перенесён из последнего согласованного `../пациент-v7/01-сегодня.png`, а не из более старого комплекта Figma v5. Прочитаны последние правки чата «Создать главный экран пациента»: выбран третий вариант, широкие контуры, цельная цветная верхняя половина, серо-зелёная палитра.

## Что можно попробовать

1. Нажать на персонажа или «Отметить настроение».
2. Выбрать состояние на семипозиционной шкале, затем уточняющие слова, факторы и необязательную заметку.
3. Получить одну из семи сцен от синего через зелёный к жёлтому с плавным движением лица.
4. Посмотреть запись в дневнике; переключать неделю/месяц, периоды и дни.
5. Добавить длительность и качество сна вручную.
6. Отметить каждый из двух вымышленных препаратов как принятый или пропущенный; исправить отметку.
7. Пройти демонстрационный опрос из трёх вопросов без диагноза и подсчёта клинического балла.
8. Открыть вкладку врача и увидеть, какие возможности ещё не подключены.

Интерфейс использует плавное появление, переходы между шагами, закрытие диалогов и перекрёстную смену изображений. Учитывает системную настройку уменьшения движения. Диалоги удерживают фокус, закрываются Escape и возвращают фокус к исходной кнопке. Цвет настроения сопровождается текстом.

## Границы этой версии

Только демонстрационные данные. Все добавленные записи находятся в памяти React, отдельно в каждой вкладке, и исчезают после обновления/закрытия страницы. Реального входа, базы данных и передачи врачу нет. Не вводите реальные медицинские сведения. Начальные записи, портрет и план лечения вымышленные; они восстанавливаются при перезагрузке.

Не реализованы: медицинская карта и интерфейс врача, настоящая переписка, запись на приём, медицинский профиль, титрация, клинические шкалы, инструкции к лекарствам, взаимодействия препаратов, AI-сводки, Apple Health и фоновые push-напоминания. В интерфейсе зависимые функции показывают пояснение, а не имитируют успешное действие.

## Стек и запуск

React 19.2, Vite 6.4.4, обычный CSS с токенами, Phosphor Icons. Растровая графика хранится локально; внешних шрифтов, трекеров и API нет. Версии зафиксированы в package-lock.json. Подробное продолжение стека: ARCHITECTURE.md.

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

Собранная версия с защитными HTTP-заголовками и service worker:

```sh
npm run build
npm test
npm run test:sites
npm start
```

По умолчанию собранная версия доступна на http://127.0.0.1:4174. PORT и HOST задаются переменными среды, по умолчанию сервер слушает только loopback. Сборка находится в dist/client. Сервер разработки не предназначен для публикации.

## PWA

Манифест, локальные иконки, standalone-режим и service worker подготовлены. Service worker создаётся только при production-сборке; в режиме разработки его нет. Кэшируется строго перечисленная публичная оболочка: HTML, CSS, JS и графика. Пользовательские записи не сериализуются и не кэшируются.

Для установки на телефон потребуется HTTPS-домен, доступный с этого телефона. Адрес 127.0.0.1 на компьютере не является адресом сайта для телефона. На iPhone: Safari → Поделиться → На экран Домой. В поддерживаемом браузере собственная кнопка установки появляется в разделе «О приложении и данных», если браузер предлагает установку. Реальная установка на iPhone и доставка push в этой итерации не проверены. Офлайн-оболочка не означает сохранение записей.

## Развёртывание

Простой путь для демонстрационного пилота: выбранный сервер → TLS reverse proxy → статический frontend. `npm start` обслуживает готовую сборку и устанавливает CSP, запрет встраивания и другие заголовки. Пример TLS-конфигурации — Caddyfile.example. Есть Dockerfile с непривилегированным пользователем и сборкой в отдельном слое; Docker-сборка здесь не запускалась. Для обычного статического хостинга примените заголовки из dist/client/_headers и проверьте, что хост их поддерживает.

Публично ничего не опубликовано. Перед размещением реальных данных необходимо завершить блок P0 из TASKS.md и SECURITY.md. Наличие заголовков и отсутствие известных уязвимостей npm не заменяет независимую проверку безопасности.

## Документы

- TASKS.md — актуальный попунктный план со статусами.
- SECURITY.md — реализованное ограничение демоверсии, модель угроз и условия допуска к реальным данным.
- ARCHITECTURE.md — текущая и следующая архитектура, модель данных, развёртывание.
- ASSETS.md — источники, созданные изображения и промпты.
- design-qa.md — визуальная проверка, сценарии и ограничения.
- qa/ — снимки работающего интерфейса и сравнение с макетом.

## Уточнения после первого просмотра

На главной настроение отмечается только за сегодня, без выбора даты. Для прошлого дня откройте Дневник, выберите день и добавьте запись. Уже добавленную отметку можно изменить кнопкой «Изменить отметку»; она не дублируется и сохраняет свой день. Время создания хранится отдельно. Запись за вчера не заменяет состояние на главной.

Фон редактора — отдельная расширенная портретная сцена с чёткими плотными контурами вокруг персонажа и редкими внешними слоями за всеми элементами. На экране слов маскот и фон плавно уменьшаются одной группой; растушёвки по бокам нет. Персонаж состоит из отдельных локальных raster assets, рот и брови двигаются, глаза не переворачиваются. Шкала по присланному референсу Apple Health: широкая полупрозрачная дорожка, белый бегунок и непрерывное движение. Семь цветовых палитр и акценты управления интерполируются через все промежуточные оттенки, в том числе во время перетаскивания. Тонкий индикатор расположен над заголовком, видимых надписей с номерами шагов нет.
