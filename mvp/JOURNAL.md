**Заметки, тестовая обработка и уведомления врача**

Реализован локальный сценарий с заглушкой. Нейросеть и внешние запросы отсутствуют. Обычный текст не классифицируется по медицинским признакам; заглушка возвращает явно подписанный фрагмент вместо настоящего саммари.

Пациент сохраняет запись в «Дневнике». В разделе «Врач» → «Доступ к заметкам» можно разрешить подключённым врачам читать заметки и отдельно включить локальные тестовые саммари, затем нажать «Сохранить разрешения». Эти же настройки доступны в настройках аккаунта. Чтение и тестовые саммари включают необходимую обработку текста; тестовая обработка не включается вместе с чтением автоматически. По умолчанию дополнительные разрешения выключены. Для будущего реального провайдера нужны новый адаптер, договорённые условия и новое согласие.

Подключение и разрешение на заметки — отдельные действия: пациент передаёт свой код из раздела «Врач», врач вводит его в «Подключить пациента», пациент подтверждает запрос. До подтверждения связи врач не получает заметки даже при включённом разрешении на чтение.

Врач открывает пациента → Дневник → Записи. Список содержит саммари и статус, исходная версия загружается по открытию. Кнопка «Заметки» в верхней панели показывает уведомления. Просмотр и принятие к рассмотрению — отдельные действия. Отзыв согласия/связи закрывает доступ и к ранее созданным уведомлениям. Уведомления существуют внутри кабинета; email/push и клиническая реакция не реализованы.

**Локальный запуск**

Полная Docker-установка по-прежнему использует `npm run docker:up`. Для разработки заметок без скачивания 15,9 ГБ справочника:

```sh
npm run docker:up -- --skip-reference
```

Миграция 017 создаёт новые public-таблицы, ограниченную роль worker и узкие SECURITY DEFINER-функции. Существующие journal-записи копируются в версию 1 в зашифрованном виде с сохранением исходного контекста расшифровки; история автоматически не анализируется. Дневник хранится в patient_entries как актуальная проекция и в journal_note_revisions как неизменяемые снимки. Справочный экспорт knowledge их не включает.

Новый секрет `.local-secrets/journal_db_password` генерируется штатным init-local-secrets; migrate устанавливает пароль роли. В web нет полномочий worker. Worker не может напрямую читать patient_entries, auth_accounts и даже таблицу снимков: только получить разрешённую задачу через функции.

Переменные: `JOURNAL_ANALYSIS_ENABLED=1`, `JOURNAL_PROVIDER=stub`, `JOURNAL_DB_PASSWORD_FILE`, существующий `DATA_KEY_FILE`. Значение provider кроме stub отклоняется, автоматической подмены реального провайдера нет. При выключенной обработке сохранение дневника продолжает работать. DB_NAME/DB_PORT позволяют использовать отдельные тестовые базы.

**API**

Машиночитаемый частичный контракт: [journal.openapi.json](journal.openapi.json).

Все изменения используют штатные Origin/CSRF/cookie-проверки. Роль и автор определяются сессией. AI-действия и врачебный notes/inbox API требуют зарегистрированных аккаунтов.

| Метод | Путь | Результат |
|---|---|---|
| PUT | /api/entries/:id | journal с expectedRevision и mutationId; возвращает саму сохранённую запись с revision/currentRevision/analysis |
| GET | /api/journal/:id/analysis | Собственный статус текущей версии |
| POST | /api/journal/:id/analysis/retry | Явный ограниченный повтор; история сама не запускается |
| GET | /api/care/patients/:linkId/notes | Страница без body; limit до 50, before — непрозрачный cursor |
| GET | /api/care/patients/:linkId/notes/:id?revision=N | Точная версия текста и её результат |
| GET | /api/care/alerts | Inbox и число не принятых уведомлений; limit/before |
| GET | /api/care/alerts/:id | Текст, результат, состояние уведомления |
| POST | /api/care/alerts/:id/seen | Просмотр с expectedStateRevision |
| POST | /api/care/alerts/:id/acknowledge | Принятие к рассмотрению с expectedStateRevision |

В PUT нужны стабильный mutationId UUID для одного сохранения и expectedRevision=0 для новой записи. Повтор идентичного запроса не создаёт версию/job. Разный текст с тем же mutationId и конкурентное изменение дают 409; отсутствие версии — 428. При конфликте редактор позволяет загрузить актуальную версию, сохранив предыдущий черновик в памяти.

POST /api/auth/consents принимает дополнительный journalAiProcessing и при включении providerPolicyVersion=`local-stub-2026-10-20-v1`. Нужны healthData и journalProcessing. journalSharing по-прежнему независимо управляет чтением врача. Согласия обновляются с expectedConsentUpdatedAt. Старый клиент, не передавший AI-флаг, не может молча сохранить включённую обработку.

Очередь: queued/running/retry_wait/succeeded/failed/cancelled. Неполученный результат не считается обычным состоянием пациента. Lease действует 120 секунд, до четырёх попыток; ошибка не содержит текста модели. Транзакции финализации проверяют epoch согласия и token аренды, сохраняют результат и алерты атомарно. Запоздалый анализ старой версии не меняет последнюю версию; алерт сохраняет ссылку на свой оригинал.

**Только для синтетической проверки**

Явные метки `[TEST:elevated]`, `[TEST:urgent]`, `[TEST:indeterminate]` выбирают сценарий заглушки. Без меток возвращается routine, который означает только сценарий заглушки, а не заключение о безопасности. Эти метки не являются способом оценки реальных записей.

```sh
npm test
npm run build
```

`scripts/check-journal.mjs` требует новую пустую мигрированную БД с именем `compass_journal_qa_<hex>`, DB_NAME/DB_HOST, файлы runtime/admin/worker-паролей и ключа. Скрипт сам поднимает временный loopback API и создаёт только синтетические аккаунты. Проверяет RLS, шифрование, согласия, идемпотентность, две конкурентные записи, два worker, обратный порядок ответов, отзыв в процессе, истёкший lease, четыре ошибки и повторную обработку, inbox и подтверждения. На рабочей базе запуск запрещён.

Проверено на локальном PostgreSQL 17: сквозной сценарий и фактический pg_dump knowledge при наличии заметок исключает персональные/AI таблицы. Полный Docker-запуск и 15,9-ГБ восстановление в этой среде не проверялись, поскольку Docker отсутствует.
