# Руководство по запуску презентационного стенда

Актуально на 27 октября 2026. Этот файл позволяет поднять локальный MVP из репозитория и открыть кабинеты пациента и врача для презентации. Все команды ниже, кроме клонирования, выполняются из каталога `mvp`.

Используйте изолированный **presentation-стенд**: приложение `http://127.0.0.1:4176/`, PostgreSQL `127.0.0.1:55434`. Он создаёт свои ключи, роли БД и вымышленные аккаунты. Полный справочник для этого запуска не нужен. Обычный `npm run docker:up` по умолчанию скачивает большой справочный снимок — для этого показа его запускать не требуется.

## 1. Подготовить компьютер и код

Нужны доступ к приватному репозиторию, Git, Node.js **24** с npm и установленный PostgreSQL **17**. Для PostgreSQL должны быть доступны серверные утилиты `initdb`, `pg_ctl`, а также `psql`; только клиента PostgreSQL недостаточно. Запускайте от обычного пользователя: `initdb` не работает от root. Docker для presentation-режима не нужен.

Если репозитория ещё нет:

```sh
git clone git@github.com:zdornik/compas.git
cd compas/mvp
```

Если копия уже есть, сначала проверьте `git status`: сохраните чужие незавершённые изменения и не делайте принудительный сброс. На чистой ветке `main` обновление выполняется из корня репозитория:

```sh
git pull --ff-only origin main
cd mvp
```

Руководство по разработке находится в [разработке комплекта](distribution/macos/DEVELOPER-README.md).

Скрипт ищет PostgreSQL в `/opt/homebrew/opt/postgresql@17/bin`, затем `/usr/lib/postgresql/17/bin`, затем в `PATH`. Для другого расположения задайте `PG_BIN`, например:

```sh
# macOS с Homebrew на Intel, если PostgreSQL 17 установлен здесь:
export PG_BIN=/usr/local/opt/postgresql@17/bin
```

Node можно проверить командой `node --version`, PostgreSQL — `"$PG_BIN/pg_ctl" --version` при заданном `PG_BIN`, иначе `pg_ctl --version` при наличии утилиты в `PATH`. Должна использоваться версия PostgreSQL 17. Управление процессами рассчитано на POSIX; нативный Windows не проверялся.

## 2. Первый запуск

```sh
npm ci
npm run build
npm run presentation:prepare
npm run presentation:start
npm run presentation:check
```

`prepare` создаёт отдельный кластер в `qa/presentation/postgres`, применяет миграции и создаёт демонстрационный набор. Глобальную службу PostgreSQL запускать не нужно: скрипт управляет своим кластером. Порты 4176 и 55434 должны быть свободны от посторонних процессов.

`start` запускает API и обработчик заметок в фоне. Успешная проверка выводит JSON с `ready: true`, адресом стенда, `provider: "stub"` и списком миграций. В текущей версии их 21. Проверка действительно сохраняет заметку «Проверка готовности стенда» и ждёт обработки до 10 секунд; её появление в дневнике ожидаемо.

Откройте приложение в браузере. Одного запуска Vite (`npm run dev`) недостаточно для показа БД, авторизации и заметок.

## 3. Где взять логины и пароль

После `presentation:prepare` откройте **локально** файл `mvp/qa/presentation/accounts.json` относительно корня репозитория. Он не приходит из Git: каждый компьютер создаёт собственные аккаунты и случайный пароль.

| Кабинет | Логин в подготовленном наборе | Поле файла |
| --- | --- | --- |
| Основной пациент | `patient@compass.example.invalid` | `patient` |
| Врач | `doctor@compass.example.invalid` | `doctor` |
| Другой пациент без связи с врачом | `other@compass.example.invalid` | `otherPatient` |
| Пароль для всех трёх тестовых аккаунтов этого стенда | Случайное значение, смотрите файл | `password` |

Источником учётных данных служит файл **на том компьютере, где запущен стенд**. Не подставляйте прежний пароль с другого компьютера. Почтовые адреса вымышленные; подтверждения почты здесь нет.

Основной пациент уже связан с врачом, согласия для чтения заметок и локальной тестовой обработки включены. В наборе есть 14 дней настроения/сна и две заметки, в том числе сигнальная. У `otherPatient` связи нет: он предназначен для проверки изоляции, а не основного показа.

`prepare` при повторном запуске сохраняет существующие записи, аккаунты и ключи. `reset` создаёт набор заново и **меняет пароль аккаунтов** — после него перечитайте файл.

Файл аккаунтов, каталог `qa/presentation/secrets`, кластер, журналы и приватные бэкапы остаются вне Git. Передавать локальные ключи или пароли другого экземпляра не нужно. Не вставляйте значение пароля в коммиты, отчёты или снимки экрана.

## 4. Открыть оба кабинета одновременно

1. В первом окне откройте `http://127.0.0.1:4176/#patient`. В общей форме входа заполните «Электронная почта» логином из поля `patient`, «Пароль» — значением `password`, нажмите «Войти».
2. Во втором окне того же браузера откройте `http://127.0.0.1:4176/#doctor` и войдите логином из поля `doctor` с тем же тестовым паролем.
3. Расположите окна рядом. Врач увидит подключённого тестового пациента в «Обзоре» / «Пациентах».

Пациент и врач могут быть открыты в одном браузерном профиле: у ролей разные cookie. Роль определяется сервером по аккаунту; `#doctor` само по себе не выдаёт права врача. Для показа используйте зарегистрированные аккаунты, а не гостевой режим.

Если нужно открыть общую форму входа из уже открытого кабинета, нажмите «Сменить аккаунт». Настоящий выход находится у пациента в «Настройки и приватность», у врача в «Учётная запись» → «Выйти из учётной записи». Для двух окон выход из первого аккаунта не требуется.

Для одновременной проверки **двух пациентов** нужны разные браузерные профили/контексты: повторный вход в той же роли заменяет её сессию и в других окнах.

## 5. Быстрый сценарий проверки перед показом

1. **Пациент:** «Дневник» → «Записи» → «Новая запись». Сохраните вымышленную обычную заметку. **Врач:** откройте подключённого пациента → «Дневник» → «Записи» и дождитесь тестового саммари.
2. Создайте у пациента ещё одну заметку с текстом `[TEST:elevated] Это вымышленная запись для демонстрации уведомления`. У врача нажмите «Заметки» в верхней панели → «Тестовый сигнал». Проверьте исходный текст и ответ заглушки, нажмите «Принять к рассмотрению».
3. **Пациент:** «Врач» → «Запросить приём», выберите будущее свободное время, отправьте запрос. **Врач:** «Календарь» → «Подтвердить». У пациента должен появиться статус подтверждённого приёма.
4. **Врач:** «Календарь» → «Назначить приём», выберите другое свободное время. Прямое назначение появится у пациента. Время показывается по Москве.

Окна обновляются автоматически; оставляйте нужное окно видимым или возвращайте ему фокус. Изменения заметок/уведомлений обычно подхватываются очередным опросом около 5 секунд, приёмов — около 10 секунд. Это интервалы обновления интерфейса, не гарантия времени обработки.

Анализ выполняет **локальная заглушка**. Маркер выбирает тестовый сигнал, текст не отправляется внешней нейросети и состояние человека не классифицируется. Уведомление отображается в приложении; push/email не подключены. Не используйте настоящие медицинские данные.

Полный сценарий выступления на 7–9 минут — [DEMO-SCRIPT.md](DEMO-SCRIPT.md). Отзыв доступа показывайте последним: он закроет карту врачу и отменит будущие приёмы, поэтому следующие сцены могут стать недоступны.

## 6. Справочник на компьютере коллеги

При первом запуске справочник **пустой**: это не мешает заметкам и приёмам. Полный корпус сейчас не загружаем. Без лекарственного каталога не планируйте показ поиска препаратов и проверки назначения.

Если отдельно передан небольшой публичный пакет образца КР 301_3, положите `sample.json` и каталог `blobs` в `mvp/qa/presentation/reference/`, затем выполните:

```sh
npm run presentation:reference
npm run presentation:check
```

Этот пакет содержит один официальный документ на 125 страниц, PDF и 25 изображений, без пациентских данных. Он не хранится в Git и не появится после клонирования автоматически. Если его нет, пропустите сцену справочника. Вариант `--from-local-reference` предназначен для компьютера, где образец уже есть в основной БД; для чистого компьютера коллеги он не подходит.

## 7. Повторный запуск, обновление и проблемы

Остановить стенд, сохранив данные:

```sh
npm run presentation:stop
```

После обновления исходников: остановите стенд, выполните `npm ci`, `npm run build`, `npm run presentation:prepare`, затем `npm run presentation:start` и `npm run presentation:check`. `prepare` применит новые миграции без сброса набора. Если код не менялся, достаточно `presentation:start` и `presentation:check`.

| Симптом | Что проверить |
| --- | --- |
| Не найдены `initdb`, `pg_ctl`, `psql` | Установлен ли полный PostgreSQL 17; укажите правильный `PG_BIN`. |
| Порт занят / ошибка принадлежности экземпляра | Проверьте владельца порта 4176 или 55434. Не завершайте посторонние процессы автоматически и не меняйте фиксированные порты только в одной настройке. |
| Вход не проходит | Адрес именно `127.0.0.1:4176`; логин основного пациента или врача, пароль из текущего `accounts.json`; после reset пароль уже другой. Не используйте `localhost` вместо `127.0.0.1`: API проверяет origin/host. |
| Слишком много неудачных попыток | Не перебирайте пароли. Сверьте текущий файл аккаунтов и дождитесь срока из сообщения / `Retry-After`. Не отключайте защиту входа. |
| Врач не видит заметки | Открыт основной `patient`, связь активна. У пациента «Врач» → «Доступ к заметкам»: разрешены чтение и тестовая обработка, изменения сохранены через «Сохранить разрешения». Обработка старых записей не запускается автоматически — сохраните новую тестовую заметку после включения согласия. |
| Саммари не появляется | Выполните `presentation:check`; проверьте обработчик и `qa/presentation/application.log`. HTTP health сам по себе не проверяет обработку заметок. |
| Проверка сообщает о разных сборках API/интерфейса | После `npm run build` выполните `presentation:stop`, затем `presentation:start` и `presentation:check`; обновите страницы браузера. |
| Справочник пуст | Нормально без отдельно переданного sample-пакета. Не запускайте восстановление полного Release ради этого показа. |

Журналы находятся в `qa/presentation/application.log` и `qa/presentation/postgres.log`. Изучайте их локально, не публикуя секреты и содержимое записей.

Сброс допустим только для одноразового presentation-набора, когда старые демонстрационные записи больше не нужны. Он удаляет их, создаёт свежие аккаунты и повторно импортирует sample, если пакет уже сохранён:

```sh
npm run presentation:reset
npm run presentation:start
npm run presentation:check
```

После сброса заново войдите обеими ролями с новым паролем. Не удаляйте вручную `qa/presentation`, секреты, основную БД или Docker volumes. Незавершённая первичная подготовка также может требовать `presentation:reset`; сначала изучите причину ошибки.

Врач открывает «Обзор» или «Пациенты»: показатели, фильтры имени, диагноза и препарата. В карте появились отдельные вкладки обзора, медицинского профиля, дневника, лечения и авторских заметок врача. У пациента в лечении есть серия дней и статистика отметок, на «Сегодня» — ежедневный сон с необязательным текстом.

После обновления исходников пересоберите приложение и выполните `presentation:prepare`: миграция 021 добавляет новые таблицы, существующие аккаунты и записи сохраняются. Затем перезапустите стенд. `presentation:reset` для обычного обновления не нужен. Полный справочник по-прежнему не загружается.

Для передачи новой вёрстки предпочтительна отдельная ветка Git. Интерфейс можно менять, сохранив [контракт API, расчёты, авторизацию и приватность](TRACKING.md). Файл Figma или изображение — исходник для реализации, а не готовый Git merge. Незавершённые задачи собраны в [ROADMAP.md](ROADMAP.md).
