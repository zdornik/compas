# Компас — тестовый стенд для macOS

Пакет для локального просмотра пациентского и врачебного интерфейсов. Внутри готовая сборка, исходники, серверные JavaScript-зависимости, схема БД и поддержку небольшого публичного образца справочника. Существующая база разработчика, её ключи, пароли и сессии не включены.

## Запуск

1. Полностью распакуйте ZIP в обычную локальную папку. Запускать файлы из просмотра архива нельзя.
2. Если Node.js 22+ и PostgreSQL 17 ещё не установлены, понадобится [Homebrew](https://brew.sh). Установите его по официальной инструкции. Не запускайте стенд от root или через sudo.
3. Дважды нажмите `START.command`. При необходимости он установит Node.js и PostgreSQL 17 через Homebrew, создаст отдельную тестовую БД и откроет приложение. При первом запуске нужен интернет для установки системных компонентов; npm install для просмотра не нужен.
4. Дождитесь `ready:true` и строки «Готово». Адрес: http://127.0.0.1:4176/ .
5. Войдите пациентом или врачом по данным из `DEMO-ACCOUNTS.md`. Роль определяется по логину; врач и пациент могут работать в соседних вкладках одного браузера.

Пакет подходит для Apple Silicon и Intel: нативные системные компоненты выбираются Homebrew. Полный запуск пакета проверяется на Apple Silicon; отдельный физический Intel Mac в проверке не используется. Если зависимости уже установлены, интернет для работы приложения не нужен. Для Homebrew действуют его собственные требования к macOS и инструментам разработчика. Официальные формулы: [Node.js](https://formulae.brew.sh/formula/node@24), [PostgreSQL 17](https://formulae.brew.sh/formula/postgresql@17).

## Что посмотреть

- Пациент: «Сегодня» → настроение и сон; «Дневник» → точки настроения/причины и записи; «Лечение» → отметки приёма и серия дней; «Врач» → подключение, сообщения и запрос приёма.
- Врач: «Обзор»/«Пациенты» → показатели и фильтры; карта пациента → дневник, лечение и закрытые комментарии; «Календарь» → приёмы.
- Врач уже подключён к первому тестовому пациенту. Второй пациент остаётся без подключения для проверки изоляции.
- Есть две вымышленные схемы, история отметок, 14 дней настроения/сна, результаты PHQ-9/GAD-7, комментарий врача и два примера приёмов. Названия «Демо-препарат А/Б» не являются настоящими лекарствами.
- В дневнике есть запись с маркером `[TEST:elevated]`: она демонстрирует маршрут уведомления от локальной заглушки. Это не оценка клинического риска реальной нейросетью.
- Переписка изначально пуста. Можно отправлять новые демонстрационные сообщения между этими аккаунтами.

## Остановка и сохранение

`STOP.command` останавливает только процессы и PostgreSQL этой копии стенда. Данные сохраняются. Следующий `START.command` продолжит работу; начальные записи не дублируются.

`CHECK.command` проверяет готовность и обработку тестовой заметки. Проверка добавляет одну синтетическую запись. Рабочие файлы и свежие ключи появляются в `qa/presentation`; не удаляйте эту папку для исправления ошибки и не пересылайте её вместе с реальными данными.

Стенд использует только 127.0.0.1: веб-порт 4176, PostgreSQL 55434. Если уже запущена другая копия, сначала остановите её её собственным `STOP.command`. Архив не подключается к существующей чужой БД и не меняет её пароль. После инициализации лучше не переносить папку с работающим стендом; сначала остановите его.

## Разработка

Начните с `DEVELOPER-README.md`. Для обычного просмотра пересборка не требуется. Для разработки установите полный набор npm-зависимостей командой `npm ci`, внесите изменения и выполните `npm run build`. После изменения backend или сборки остановите и снова запустите стенд.

## Если запуск не получился

- `command not found`/нет Homebrew: установите Homebrew или Node.js 22+ и PostgreSQL 17 по официальным инструкциям, затем повторите запуск.
- PostgreSQL другой версии: установите именно 17. Для нестандартной установки можно задать `PG_BIN` — папку с `initdb`, `pg_ctl`, `psql`, `pg_dump`, `pg_restore`.
- Конфликт порта/другой каталог БД: остановите другую локальную копию. Не удаляйте её файлы и не меняйте порт/имя БД наугад.
- Ошибка приложения: проверьте `qa/presentation/application.log` и `qa/presentation/postgres.log`. Успех означает `ready:true`, а не только открывшуюся страницу.

## Границы демонстрации

Используйте вымышленные сведения. Шифрование серверное AES-256-GCM; это не E2EE. Личность и квалификация врача не подтверждаются. Реальная нейросеть, push/email и видеозвонки не подключены. Приём препаратов — самоотчёт; результаты шкал — скрининг, не диагноз.

Полная справочная БД не включена и не скачивается. Если при сборке пакета предоставлен проверенный публичный образец, в комплект войдёт один официальный документ с исходником и страницами; иначе справочник будет пуст. Это не полный лекарственный каталог; для отсутствующих препаратов нельзя заявлять проверенную совместимость.
