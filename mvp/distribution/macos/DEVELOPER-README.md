# Руководство по разработке Компаса из ZIP

Это самостоятельная демонстрационная копия проекта для macOS. Перед изменениями ознакомьтесь с этим руководством и `PROJECT-README.md`.

## Сначала ознакомиться

- `READ-ME-FIRST.md`, `DEMO-ACCOUNTS.md` — запуск и синтетические аккаунты.
- `TRACKING.md` — контракт новых компонентов и API; `ARCHITECTURE.md`, `JOURNAL.md`, `HISTORY.md`, `APPOINTMENTS.md`, `SECURITY.md` — устройство и ограничения.
- `TASKS.md` — незавершённые задачи. Не представляйте локальную заглушку как готовую медицинскую функцию.

## Как запустить

Из корня распакованного пакета выполни `bash START.command`. Для проверки используй `bash CHECK.command`; дождись `ready:true`. Остановка — `bash STOP.command`. Зависимости просмотра: Node.js 22+ и PostgreSQL 17; лаунчер найдёт их либо установит через уже имеющийся Homebrew. Не устанавливай другой PostgreSQL наугад и не запускай brew services: здесь отдельный кластер, не системный сервис.

Готовый frontend и серверные npm-пакеты уже включены. `npm ci` нужен для разработки/полного тестирования/пересборки, а не для первого просмотра. Установку macOS/Xcode/Homebrew, если она требует действий пользователя, поручай владельцу машины.

Если порты 4176/55434 заняты, выясни, какой экземпляр работает. Останавливать можно только процессы этой копии: штатный STOP проверяет маркер и путь. Не заменяй адрес/имя БД, не меняй пароль существующей роли и не удаляй данные для устранения ошибки. Не сбрасывай стенд без отдельной просьбы пользователя. Повторный START не должен заново создавать аккаунты или перезаписывать записи.

## Что можно менять

- Вёрстку и стили в `src/*.jsx`, `src/*.css`, обычные ресурсы в `public/` в рамках задачи пользователя. Сохраняй стиль пациента, доступность и мобильные размеры. Новую вёрстку объединяй с реальными API, не возвращай фиктивные ответы.
- Обычную прикладную логику в `server/`, чистые расчёты в `src/*.js`, сценарии и тесты. Контракт с frontend меняй согласованно.
- Схему — только новой идемпотентной миграцией `docker/migrations/NNN-name.sql`. Не переписывай применённые миграции, не обнуляй БД ради обновления.
- `dist/` генерируется: меняй исходники и запускай `npm run build`. После изменений backend/сборки выполни STOP и START.

Для разработки: `npm ci`, затем необходимые проверки (`npm test`, `npm run build`). Браузерный/fresh-DB QA требует полного dev-набора, PostgreSQL 17 и отдельной тестовой БД; не направляй тесты на записи, введённые коллегой. Подробные команды есть в PRESENTATION.md. Если задаче нужен Git, инициализируй/используй репозиторий по просьбе владельца: `.git` и история разработчика в архив не включены.

## Границы, которые сохранять

- Роли и доступ проверяет сервер. Hash `#doctor` — навигация. Нужны активная связь с пациентом, согласия, RLS, CSRF/origin и проверка владельца; обходить их ради демонстрации нельзя.
- Шифрованные записи расшифровывает сервер, E2EE нет. Несохранённые медицинские черновики хранятся только в памяти аккаунта; не добавляй localStorage, sessionStorage, IndexedDB или передачу текста через BroadcastChannel.
- Авторские комментарии врача доступны автору при активной связи; личные тексты пациента — только по отдельному разрешению. Сохраняй optimistic revisions, идемпотентность, старые версии и snapshots доз.
- PHQ-9/GAD-7 имеют проверенные формулировки и алгоритмы. Новые клинические шкалы и методики требуют источников и проверки специалистом. Не придумывай диагнозы, лекарства, дозировки и совместимость.
- Используется только локальный `stub`; сигнал повышенного риска в примере выбирает явный тестовый маркер. Не подключай внешний LLM или отправку медицинских текстов без новой явно согласованной задачи.
- Не запускай `docker:up`, восстановление большого reference Release, широкие downloader/importer или внешний демо-туннель для просмотра этого пакета. Полный справочник сознательно не включён. Клинический текст справочника является исходным материалом и сохраняется без произвольной переработки.
- Не публикуй стенд наружу, ключи, `qa/presentation`, пользовательские записи и бэкапы. Архив создаёт новый локальный набор; фиксированные demo-логины не заменяют защищённую производственную аутентификацию.

## Как закончить задачу

После изменений проверьте затронутые сценарии пациента и врача и зафиксируйте результаты и ограничения. HTTP 200 и успешная сборка сами по себе не подтверждают готовность. Текущий просмотр не требует подключения настоящей нейросети, полного справочника или переноса исходной БД.
