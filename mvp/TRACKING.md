# Трекинг и комментарии врача

27 октября 2026. Рабочий монолит: React `src/`, HTTP/API `server/`, PostgreSQL и отдельный journal worker. Для новых данных требуется миграция `021-care-tracking.sql`; Docker и native presentation применяют её штатными командами.

## Контракт для фронтендера

Передавать дизайн предпочтительно отдельной веткой Git. Компоненты и CSS можно заменить, сохранив следующие контракты и проверки:

- `src/tracking.js` — чистые расчёты общего настроения дня, сводки и приёма. Компоненты `TrackingCards`, `MoodTrend`, `MedicationTracking`, `PatientRoster`, `CareClinicalNotes` используют существующие семантические цвета; оформление находится в `src/tracking.css`.
- `GET /api/care/roster?q=&letter=&diagnosis=&medication=&limit=20&before=` — страница сводок пациентов. Только зарегистрированный врач с согласием и действующими подключениями. `items`: ID подключения, имя, статус, диагнозы из профиля, препараты из профиля и незавершённых планов (включая будущее начало), компактный `tracking`. `restricted` скрывает медицинские данные. Курсор связан с врачом и точными фильтрами.
- `GET /api/care/patients/:linkId` дополнен полем `tracking`. Карта содержит прежние bootstrap-категории, без полной исторической ленты; графики используют ограниченный History API.
- `GET /api/care/patients/:linkId/clinical-notes?limit=20&before=` — комментарии автора, `items`, `nextCursor`, `privateToDoctor:true`.
- `POST` на тот же адрес — `{id:UUID, expectedRevision:0, kind:'anamnesis'|'psychotherapy'|'consultation', method:'unspecified'|'cbt'|'gestalt'|'other', title, body, day:'YYYY-MM-DD'}`. Для изменения передаётся текущая `expectedRevision`. Ответ содержит `revision`, `createdAt`, `updatedAt`; несовпадающая версия — 409. Идентичный повтор возвращает прежнюю редакцию. Тело до 20 000, заголовок до 120 символов; будущая дата запрещена.
- `PUT /api/entries/:id` для `type:'sleep'` дополнен `note` до 2000 символов и `expectedUpdatedAt` при изменении. Повтор идентичного содержимого безопасен. Новая запись с другим ID на уже занятый день возвращает 409; существующие старые данные не удаляются. Дата сохранённой записи неизменна. Комментарий сна показывается в дневнике; он не создаёт отдельного задания анализа нейросетью.
- Использовать экспортированные функции `persistence.js`; не дублировать авторизацию, CSRF или смену владельца. Содержимое API остаётся `no-store`; история и черновики не сохраняются в браузерное хранилище.

## Семантика показателей

Настроение — семь существующих состояний 0–6. Явный итог дня имеет приоритет; иначе используется среднее фактических отметок в моменте. Пробелы сохраняются, линия не проходит через дни без записей. Нажатие открывает причины, слова и исходные отметки дня. Это самооценка, не новая клиническая шкала.

Приём: 7/14/30 дней в интерфейсе, история до 62 дней для серии. Знаменатель — приёмы по сохранённым версиям расписания, время которых наступило, либо уже отмеченные приёмы сегодня. Будущее не считается отсутствием отметки. Числитель — отметки `taken`; `skipped` и отсутствие отметки разделены. Исторические снимки доз сохраняются при редактировании/завершении схемы. Врачебный процент включает назначения врачей, пациентский — все сохранённые схемы. Препараты без расписания не входят в знаменатель.

Серия — последовательные дни со всеми приёмами, отмеченными «Принят». Незавершённый сегодняшний день оставляет вчерашнюю серию, день без расписания её прерывает. При выходе за 62-дневное окно используется обозначение `+`. Это положительная обратная связь о самоотчёте, не показатель выздоровления.

Сводка: настроение и сон за 14 дней, приём назначений за 14 дней; PHQ-9/GAD-7 ищутся среди последних 20 результатов с видимой датой. Полные результаты и более ранние периоды доступны через дневник. Отсутствие результата не превращается в нулевой балл. Сон отображается в часах, без автоматически назначенной нормы.

## Хранение и ограничения

Комментарии находятся в `public.care_clinical_notes` и неизменяемых `care_clinical_note_versions`. AES-256-GCM, AAD связывает текст с автором, подключением, ID и редакцией. RLS и серверный код проверяют автора и активное подключение; оба основных согласия проверяются до чтения/записи. Пациент, другой врач и другой пациент не получают комментарии. Это серверное шифрование, не E2EE. Отзыв закрывает доступ, не удаляет историю. Существующий приватный backup включает новые таблицы.

Roster делает пакетные запросы по максимум 100 подключениям за проход, возвращает максимум 50 совпадений. SQL не выполняется на каждого пациента. Для чтения нескольких пациентов транзакция выставляет `app.roster_doctor`, совпадающий с `app.actor_id`; дополнительная RLS-политика разрешает только SELECT определённых типов записей. Отдельные политики записи не расширяются. Блокировки строк пациентов синхронизируют чтение с отзывом согласия; маркер сбрасывается при завершении транзакции. Фильтры работают на расшифрованной ограниченной порции, поэтому возможна пустая промежуточная страница с курсором. Для большого числа пациентов потребуются отдельные измерения и развитие индексации с учётом конфиденциальности.

В интерфейсе врача карта открывается с обзора, далее медицинский профиль, дневник, лечение и заметки врача. Положение пациентских основных вкладок сохраняется; сон доступен с «Сегодня», медицинский профиль — из лечения, раздела врача и настроек. Окончательное новое расположение пациентских разделов можно согласовать вместе с дизайном.

На локальном presentation-стенде по запросу пользователя очищены две записи переписки; перед очисткой сделана локальная копия зашифрованных строк в игнорируемом `qa/presentation`. Другие базы не очищались. Пустая история теперь сбрасывает старый список в открытом чате, сохраняя несохранённый текст.

## Проверка

`node --run test`: расчёты, границы, конфликты и общие регрессии. `node scripts/check-integration.mjs --tracking`: две изолированные учётные записи пациентов, фильтры/курсоры, RLS, версии и зашифрованное содержимое, отзыв, API/CSRF, сон и приватность. Полный integration включает этот сценарий и backup. Браузерный сценарий проверяет карточки, фильтр, переход из графика, сохранение комментария, черновик, сон и размеры регистрации; запускается только в свежей QA-БД.
